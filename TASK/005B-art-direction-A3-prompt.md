# Task 005B — Art Direction A3: Editorial Engineering × Software Evidence

## Context

We are continuing the ARTIT website visual-direction exploration.

The current preferred direction is **Art Direction A — Editorial Engineering**, but the owner review found that the original A was still somewhat too restrained and did not create enough visual pull.

Task 005A then produced an **A2 refinement**. A2 is a clear improvement, especially in the hero:
- the large software-evidence area creates a real composition rather than a text-only layout;
- the `FOLYAMAT → ALKALMAZÁS → INTEGRÁCIÓ → ADAT` line is quieter and more contemporary than the earlier boxed treatment;
- tonal surfaces and reduced metadata noise help;
- the asymmetric hero has more direction and potential.

However, A2 is **not yet the final art direction**.

The owner’s target feeling remains:

> **freshness + clarity + harmony + something that pulls you in**

The site should feel contemporary and emotionally engaging without becoming fashionable-for-fashion’s-sake, decorative SaaS, playful startup design, or generic agency styling.

The current conclusion is important:

> **The palette and typography are not the primary problem. The remaining gap is mainly compositional.**

We therefore want an **A3**, not a new direction.

A3 must be a deliberate hybrid of the strongest qualities of **A + A2**, with one final layer of contemporary art direction focused on:
- visual pull,
- composition,
- software imagery treatment,
- rhythm,
- controlled visual tension.

Do **not** reopen the entire design system.

---

## Goal

Create a final-candidate **A3 art-direction prototype** that feels:

- fresh,
- clean,
- harmonious,
- contemporary,
- confident,
- technically credible,
- editorial rather than templated,
- distinctive without being loud,
- visually attractive enough to create an emotional pull.

The desired reaction is not “this has lots of design.”

It is closer to:

> “This feels precise, modern and considered — I want to keep looking.”

A3 should still unmistakably belong to the same ARTIT design family established in Tasks 004A–004C and explored through A/A2.

---

# 1. Core direction: A + A2 hybrid

Do not invent Direction D.

Use **A — Editorial Engineering** as the conceptual base.

Preserve from A where useful:
- editorial composition,
- engineering precision,
- restrained technical vocabulary,
- strong left-aligned typography,
- whitespace,
- quiet confidence,
- subtle system/evidence cues,
- content-first hierarchy.

Preserve from A2 where useful:
- large software evidence as a meaningful visual counterweight,
- asymmetric composition,
- fewer metadata decorations,
- quiet tonal surfaces,
- the simplified process vocabulary,
- cleaner visual hierarchy.

Then improve the combination through **composition rather than decoration**.

---

# 2. Critical design principle

The page currently risks becoming too orthogonal:

> rectangle → line → grid → text → line → grid → text

That is competent and credible, but too sterile.

A3 must introduce **controlled visual tension** without losing clarity.

Preferred tools:

- crop,
- overlap,
- asymmetry,
- whitespace,
- scale contrast,
- alignment shifts,
- selective interruption of the grid,
- stronger relationship between text and software evidence,
- more varied section rhythm.

Avoid solving this with additional decorative components.

The objective is **not more visual elements**.

The objective is **better composition**.

---

# 3. Hero — highest priority

The A2 hero is the strongest part of the current experiment and should be evolved rather than replaced.

Current basic structure:

`TEXT | SOFTWARE EVIDENCE`

is directionally correct, but still reads too much like two independent rectangular columns.

## Required experiment

Turn the software evidence into an **editorial crop**, not merely a screenshot container.

The viewer should not feel:

> “Here is a screenshot.”

They should feel:

> “I am looking into a real working system.”

Explore a restrained treatment such as:

- a deliberately cropped software screenshot/evidence surface;
- part of the visual extending toward or beyond the normal content grid;
- a subtle overlap or relationship with adjacent whitespace/grid boundaries;
- selective clipping that suggests the UI continues beyond the frame;
- possibly one secondary detail/crop if it materially improves depth;
- stronger scale contrast between hero copy and product evidence.

Do not create fake product UI.

If no real approved screenshot asset is currently available, keep the evidence area as an explicit placeholder, but design its **geometry/composition/crop behavior** so the intended final treatment is clear.

The placeholder must not pretend to be real software.

## Hero constraints

Keep:
- current approved hero copy unchanged;
- current CTA copy unchanged;
- current navigation/header structure unless a tiny spacing adjustment is necessary;
- the process vocabulary concept (`FOLYAMAT → ALKALMAZÁS → INTEGRÁCIÓ → ADAT`) unless its exact placement needs compositional refinement.

Do not:
- add gradients;
- add blobs/orbs;
- add floating SaaS cards;
- add fake dashboards;
- add abstract 3D objects;
- add generic illustrations;
- add decorative animation;
- add client JS.

The hero should feel more contemporary primarily because of **layout, crop, scale and whitespace**.

---

# 4. Problem section — recover more of A

The A2 Problem section is cleaner, but the centered heading feels more like a conventional website section headline and loses some of A’s editorial character.

A3 should reconsider this.

## Direction

Prefer a **left-organized editorial heading composition** over a centered marketing-section treatment.

The section should retain:
- the existing approved copy;
- the six symptoms;
- clear scanability;
- strong information hierarchy.

But avoid making the six symptoms feel like a generic two-column feature grid.

Use A’s editorial quality together with A2’s calmer tonal treatment.

Possible techniques:
- asymmetric two-column distribution;
- one tonal field paired with open whitespace;
- staggered alignment;
- subtle vertical logic;
- varied grouping without turning items into cards;
- selective use of numbering/metadata only where it improves rhythm.

Do not force all six items into identical repeated boxes.

The section should feel composed, not componentized.

---

# 5. Rhythm across the page

A3 should demonstrate that the design language can sustain a full website, not only a hero.

Review the vertical sequence of the prototype and intentionally vary:

- dense vs. open sections,
- text-heavy vs. evidence-heavy moments,
- standard vs. major spacing,
- left/right visual weight,
- light tonal surface vs. plain background,
- occasional dark emphasis only where justified.

Avoid a page where every section uses the same container + heading + grid rhythm.

At the same time, do not create arbitrary variation.

The page should feel **harmonious**, with tension inside a coherent system.

---

# 6. Color and typography: do not reopen

Do **not** redesign the palette.

The current Restrained Industrial Neutral palette remains the baseline.

Do **not** introduce a new accent color merely to create freshness.

Do **not** change the established font families.

Do **not** reopen the Task 004C typography calibration unless a very small local adjustment is objectively necessary for the A3 composition.

Current foundation remains:

- Work Sans for primary typography;
- Space Mono for metadata/system language;
- display/H1 600;
- H2 600;
- H3 500;
- lead 500;
- body 400;
- existing container architecture;
- existing radius philosophy;
- existing CTA/link language.

Freshness must come primarily from **composition**.

---

# 7. Restraint / anti-pattern guardrails

A3 must NOT drift toward:

- trendy SaaS landing-page aesthetics;
- oversized rounded cards everywhere;
- glassmorphism;
- gradients;
- neon;
- soft floating blobs;
- gratuitous shadows;
- fake browser chrome;
- fake dashboards;
- generic code snippets;
- excessive monospace;
- cyberpunk aesthetics;
- brutalism for its own sake;
- huge black areas merely for drama;
- decorative motion;
- visual gimmicks that will age quickly.

The ARTIT brand should feel modern because it is **well designed**, not because it imitates a current design trend.

---

# 8. Real software evidence

Real software imagery is strategically important to this direction.

However:

- never fabricate UI;
- never invent customer/product facts;
- never imply a placeholder is a real screenshot;
- never use unapproved customer-identifying information.

If real screenshot assets already exist in the repository and are clearly safe/approved for this experimental page, you may use them.

Otherwise use explicit placeholders and document exactly what kind of real asset should eventually replace them.

A3 should make it obvious **how real software evidence will live in the composition**.

---

# 9. Scope

This is still an **art-direction experiment**, not final homepage production.

Prefer modifying/creating the existing experimental art-direction page rather than prematurely refactoring the production component architecture.

Do not:
- rewrite approved content;
- implement unrelated homepage sections;
- change content models unnecessarily;
- add dependencies;
- add a JS framework;
- add client-side hydration;
- commit unless the established workflow explicitly requires it.

Keep the experiment isolated and clearly non-production/noindex as established in previous tasks.

---

# 10. Responsive behavior

A3 must be visually checked at:

- 390px
- 768px
- 1440px
- 1920px

Desktop is especially important for evaluating the art direction, but mobile must not become a collapsed afterthought.

On narrow screens:
- preserve hierarchy;
- avoid awkward giant headline wrapping;
- keep software evidence meaningful;
- allow editorial crops to simplify gracefully;
- avoid horizontal overflow;
- keep CTAs natural-width rather than automatically full-width unless there is a strong reason;
- preserve adequate whitespace without producing enormous empty gaps.

No horizontal overflow at any required viewport.

---

# 11. Accessibility and performance constraints

Preserve the existing project standards:

- semantic HTML;
- keyboard accessibility;
- visible focus states;
- adequate contrast;
- reduced-motion handling;
- zero unnecessary client JS;
- no external font requests;
- no new dependencies unless absolutely unavoidable — and for this task they should not be necessary.

Run:
- `npm run check`
- `npm run build`

Also verify generated output remains free of accidental client scripts if the current architecture is zero-JS.

---

# 12. Visual review workflow — mandatory

Do not judge A3 from code alone.

Use a real browser and capture screenshots at all four required widths.

Specifically inspect:

## Hero
- Does the software evidence feel integrated into the composition rather than placed beside the text?
- Is there real visual pull?
- Does the eye know where to go?
- Is the whitespace intentional?
- Does the crop feel editorial rather than arbitrary?
- Does the hero still feel calm and credible?

## Problem section
- Has the editorial character of A been recovered?
- Is it more interesting than a generic two-column grid?
- Are the six symptoms easy to scan?
- Is the section harmonious rather than busy?

## Whole page
- Does the rhythm vary enough?
- Does the design feel fresher without relying on trendy decoration?
- Does it still feel like ARTIT?
- Is there any section that becomes sterile or excessively engineered?
- Is there any element that feels like visual noise rather than useful tension?

If an obvious visual issue appears during screenshot review, fix it before reporting completion.

# Success criterion

A3 succeeds if it feels recognizably descended from **Editorial Engineering**, gains the useful software-evidence strength of A2, and becomes noticeably more **fresh, harmonious and visually magnetic** without becoming louder, trendier or more decorative.

The intended result is:

> **editorial precision + real software credibility + contemporary compositional confidence**

Not:

> **more UI decoration**.
