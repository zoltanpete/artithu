# Task 005A.1 — Art Direction Exploration

## Status
`READY`

# Claude execution prompt

We are continuing the ARTIT.hu greenfield website project.

Task 005A implemented the first production homepage slice (Hero, Problem / Recognition, Decision / What ARTIT does) and passed technical review. Owner visual review found an art-direction gap: the page is credible, precise and senior, but feels too sombre, conservative and slightly old-school. It needs more contemporary software-engineering character, freshness, visual energy, curiosity and emotional pull without losing trust or restraint.

Treat this as an **art-direction problem**, not primarily a font-size/padding problem.

Your task is to create three meaningfully different comparison prototypes. Do not choose a winner and do not replace production `/`.

## 2. Locked foundation

Do not replace/reopen Work Sans, Space Mono, self-hosted fonts, Restrained Industrial Neutral core palette, Task-004C typography hierarchy/body foundation, containers, section-spacing token system, radius philosophy, CTA/link language, accessibility principles, zero-client-JS baseline, approved homepage message architecture/navigation/routes.

Do not solve modernity by changing fonts or brand palette. Explore composition, hierarchy, rhythm, technical visual language and controlled surface treatment.

## 3. Emotional target

Target: **senior + engineering + precise + contemporary**.

The visitor should feel: serious company; understands business-critical software; technically current; thinks in systems; tasteful/disciplined; trustworthy with important operations; visually interesting enough to keep exploring.

Add restrained “this is interesting” energy. Avoid startup hype, trendy-for-trendy's-sake, youthful playfulness, sci-fi, AI clichés, generic SaaS marketing and agency-showreel aesthetics.

## 4. Three directions

Create genuinely different directions using the same underlying copy/message.

### A — Editorial Engineering
Evolve the restrained editorial direction using stronger/asymmetric grid, horizontal composition, meaningful technical annotations/metadata, system/process relationships, alignment/rule systems and editorial whitespace with tension. Typography should interact with technical information.

Feeling: **senior engineering publication / precise systems thinking / contemporary B2B technology**.

### B — Software as Evidence
Make real software/systems tangible through software-evidence language: interface/screenshot framing concepts, system states, application/integration/data relationships, technical captions, structured metadata and evidence-like composition.

Never fabricate customer UI, fake dashboards or fake proof. If approved screenshots are unavailable here, use clearly abstract/non-deceptive structural placeholders demonstrating where real evidence could live.

Feeling: **we actually build systems / tangible engineering / software is the proof**.

### C — Contemporary Industrial Digital
Push composition/contrast furthest while retaining restraint: bolder scale relationships, confident asymmetry, stronger light/dark or surface transitions, larger structural gestures, controlled cropping/overflow, semantic geometric/system motifs and stronger visual tension.

Feeling: **confident / contemporary / engineered / distinctive**.

This is the boldest option but must remain credible for senior B2B software engineering.

## 5. Technical visual language

Explore an ARTIT-specific language based on real systems thinking, e.g. PROCESS → APPLICATION → INTEGRATION → DATA; nodes, connection lines, flow, system boundaries, state labels, metadata, structural markers, integration relationships, screenshot annotations and modular information blocks.

Every technical element must communicate systems/software/engineering. No meaningless technical decoration.

## 9. Baseline preservation

## 10. Palette and typography

Core palette and fonts remain locked. You may change proportions/roles of existing colors: deliberate dark surfaces, structural accent, surface/background contrast, rules, metadata, controlled color blocking. If an alpha treatment is needed, derive it from existing colors and report it.

Typography weights/families remain locked. You may explore composition, wrapping, scale relationships within existing responsive system, spatial relationships with metadata, columns and safe orientation/cropping. Readability wins.

## 11. Static modernity

No animation as modernization. Preserve zero client JS. No scroll effects, parallax, cursor effects, canvas/WebGL or animation libraries.

## 12. Prohibited shortcuts

No gradients, glassmorphism, neon glow, 3D blobs, AI abstract art, stock photography, generic code screenshots, fake terminals/dashboards/charts, random dot grids, meaningless circuit patterns, purposeless giant numbers, excessive rounded cards, pill overload, bento-everything or generic SaaS icon grids. Do not copy another company's identity.

## 13. Problem section

The current scattered recognition statements are strategically useful but visually underpowered. Reinterpret them in every direction so they feel like **symptoms of a fragmented operating system/business process**, not quotations floating in whitespace.

Preserve human recognizability and the idea that the business and its supporting tools are no longer in sync. Do not turn them into six identical cards.

## 14. Hero

1. positioning
2. comprehension
3. CTA
4. visual interest

The visitor must understand ARTIT before admiring the design.

## 15. Header

## 16. Responsive/accessibility/performance

No new runtime dependency/framework/client JS/external fonts/large image dependency/animation package.
